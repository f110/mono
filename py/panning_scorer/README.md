# panning-scorer

流し撮り写真の失敗(被写体ぶれ)を自動スコアリングし、XMP サイドカーの
`xmp:Rating` に書き込む一次スクリーニングツール。最終判定は人間が行う。

## 仕組み

1. EXIF の焦点距離・シャッター速度から流し撮り意図を判定。非流し撮りはレーティングしない (設計 §4.5)
2. NEF の埋め込み JPEG プレビューを抽出 (フル RAW デコードはしない, 設計 §5)
3. グレースケール化・ダウンサンプル後、N×N グリッドの Laplacian 分散を計算
4. 中央+周辺の絶対シャープネスの重み付き和を正規化してスコア(0.0〜1.0)化 (設計 §4)
5. スコアを Rating(-1〜5) へ変換し、既存メタデータを壊さず XMP へ書き込む (設計 §6)

## 依存

`bazel run` する場合、pip 依存 (rawpy / opencv-python-headless / numpy /
python-xmp-toolkit / exifread) は `//:requirements.txt` 経由で解決される。

以下はホストに必要なネイティブライブラリ:

- `python-xmp-toolkit` は実行時に Exempi(libexempi) を ctypes で読み込む。
  macOS では `brew install exempi` が必要。
- LibRaw / OpenCV は各 wheel に同梱されるため個別インストール不要。

## 使い方

```sh
# ドライラン: 書き込まずスコア分布を CSV に出力 (閾値調整用, 設計 §8.1)
bazel run //py/panning_scorer:panning-scorer -- --dry-run --csv /tmp/scores.csv /path/to/nef_dir

# 本番: XMP へ Rating を書き込む (設計 §8.2)
bazel run //py/panning_scorer:panning-scorer -- /path/to/nef_dir

# CSV から XMP を更新: 再スコアリングせず閾値・判定係数だけ再適用 (設計 §8.4)
bazel run //py/panning_scorer:panning-scorer -- --from-csv /tmp/scores.csv
```

主なオプション (設計 §10 の調整対象):

| オプション | 既定 | 説明 |
|-----------|------|------|
| `--dry-run` | off | 書き込まずスコアのみ算出 |
| `--csv PATH` | なし | スコア分布 CSV 出力 |
| `--from-csv PATH` | なし | CSV から XMP を更新(再スコアリングなし)。`--dry-run` 併用で分布のみ確認 |
| `--workers N` | 性能コア数 | 並列ワーカー数。`1` で直列実行 |
| `--downsample PX` | 1600 | ダウンサンプル長辺 |
| `--grid-n N` | 4 | グリッド分割数(3 以上) |
| `--center-norm V` | 737 | スコア合成 min(center/center_norm+surround/surround_norm,1) の中央側正規化 |
| `--surround-norm V` | 224 | 同スコア合成の周辺側正規化 |
| `--panning-shutter-factor V` | 5.0 | 流し撮り判定: シャッター分母 < 焦点距離/V なら流し撮り |
| `--no-panning-filter` | off | 流し撮り判定を無効化し全ファイルをレーティング |

## 推奨運用手順 (設計 §8.3)

1. 数百枚のサブセットで `--dry-run --csv` を実行し、分布と実測速度を確認
2. 分布と `_Rejected` 等の正解に基づき center_norm・Rating 境界・流し撮り判定係数を調整
3. 全ファイルで `--dry-run --csv` を実行して Rating 分布を最終確認
4. `--from-csv` で CSV から XMP へ書き込み (再スコアリング不要, 設計 §8.4)
5. ビュワーで Rating ソートし、人間が最終確認

## 設計

本文中の「§X」はこの節番号を指す。実装で確定した判断(Python 実装、ネイティブ
ライブラリ利用、サイドカー欠如時は新規作成)を反映済み。

### 1. 概要

大量に撮影した RAW 写真(Nikon NEF)を高速に選別するため、流し撮りの失敗写真
(被写体が止まっていない写真)を自動でスコアリングし、XMP サイドカーの Rating へ
書き込む。最終判定は人間が行い、本ツールは一次スクリーニングに徹する。

**目的**

- 流し撮りで量産される「被写体ぶれ」写真を自動的に低評価にする
- 人間は Rating でソート・フィルタして確認作業を効率化する
- 全自動での削除は行わず、スコアリングに徹する(安全側の設計)

**非目標** — 完全自動での削除・除外、芸術的な良し悪しの判定、RAW の現像・補正処理。

### 2. 要件

機能要件:

| ID | 要件 |
|----|------|
| FR-1 | Nikon NEF が入ったディレクトリを入力として受け取る |
| FR-2 | 各写真に被写体シャープネスに基づくスコア(0.0〜1.0)を算出する |
| FR-3 | スコアを XMP Rating(-1〜5)へ変換し同名 `.xmp` サイドカーへ書き込む |
| FR-4 | 既存 XMP の他メタデータを破壊せず更新する |
| FR-5 | ドライラン(書き込みなし・スコア出力のみ)をサポートする |
| FR-6 | スコア分布を CSV で出力し閾値調整に利用できる |

非機能要件:

| ID | 要件 |
|----|------|
| NFR-1 | 1万ファイルを20〜30分以内(1枚平均200ms以内)に処理する |
| NFR-2 | macOS 専用(Apple Silicon 想定) |
| NFR-3 | 処理失敗ファイルはスキップしログ退避、全体処理は継続する |
| NFR-4 | 閾値・グリッド分割等のパラメータは外部から調整可能とする |

### 3. アーキテクチャ

処理パイプライン:

```
[NEF群] → ⓪意図判定(EXIF) → ①プレビュー抽出 → ②スコアリング → ③Rating変換 → ④XMP書き込み → [CSV/ログ]
```

コンポーネントと実装モジュールの対応:

| コンポーネント | 責務 | 実装 |
|----------------|------|------|
| Panning Gate | EXIF から流し撮り意図を判定し非流し撮りを除外 | `exif.py` / `intent.py` |
| Preview Extractor | NEF から埋め込み JPEG を抽出しグレースケール化 | `preview_extractor.py` |
| Scorer | グリッド Laplacian 分散でシャープネスを評価 | `scorer.py` |
| Rating Mapper | スコアを Rating へ変換 | `rating_mapper.py` |
| XMP Writer | XMP へ Rating を安全に書き込む | `xmp_writer.py` |
| Orchestrator | 走査・並列実行・進捗・結果集約 | `orchestrator.py` / `pipeline.py` / `main.py` |

Scorer(アルゴリズム)と Rating Mapper(閾値)は実験による調整対象として差し替え可能。

### 4. アルゴリズム

**方針** — 人間の採否は「画面(中央+周辺)がどれだけシャープに写ったか」でよく説明できた。
中央と周辺の絶対シャープネス(Laplacian 分散)の重み付き和をスコアの基準とする。

グリッド分割 Laplacian 分散:

1. プレビューをグレースケール化し長辺を一定サイズ(既定1600px)へダウンサンプル
2. N×N(既定4×4)のグリッドに分割
3. 各セルの Laplacian 分散(シャープネス指標)を計算
4. 中央2×2領域の平均を `center_sharpness`、残り(周辺)の平均を `surround_sharpness` とする
5. 正規化してスコア化: `score = min(center/center_norm + surround/surround_norm, 1.0)`

実データ校正(2026-06-30, レビュー済み rating≥1 プール)での keep/reject 分離力(AUC)は
ratio 0.40(無力) < center 0.71 < surround 0.76 < center+surround 0.83。当初柱にした中央/周辺比は
役に立たず、中央と周辺の絶対シャープネスの和が最良だった。重みは各特徴の標準偏差に反比例
(z-sum相当)。比(ratio)は診断用に CSV へ残す。

【暫定】ラベルは旧ツールが rating≥1 とした行のみ(未レビュー領域は不明)のため境界は暫定。
新指標で dry-run し上位を再レビューして確定する必要がある(feedback-loop)。

限界と拡張(§4.4) — グリッド固定のため被写体が中央にない構図では精度が落ちる。シャープネスの
尺度はレンズ・設定・撮影ごとに変わるため `--center-norm`/`--surround-norm` で再校正する。将来的に
被写体検出(YOLO 等)でバウンディングボックス内シャープネスを評価する拡張が可能だが、
速度予算(200ms)と相談が必要。

流し撮り意図の判定(§4.5) — そもそも流し撮りを意図していない写真はスコアリング対象外とし
Rating を付けない。焦点距離とシャッター速度のみで判定し、シャッター速度の分母が
焦点距離/factor(既定5)より小さいとき流し撮り意図とみなす(例: 600mm なら 1/100 は流し撮り、
1/200 は非流し撮り)。EXIF を取得できない場合は判定不能として評価を続行する(fail-open)。
判定は preview 抽出より前に行い、非流し撮りは以降の処理を省く。`--no-panning-filter` で無効化可。

### 5. RAW からのデータ取得

フル RAW デコード(demosaic 込み)は1枚数百ms〜秒で200ms予算を超過する。ブレ判定に必要
なのは被写体シャープネスのみでフル解像度・フルビット深度は不要。よって NEF に埋め込まれた
JPEG プレビュー(LibRaw/rawpy の `extract_thumb`)を抽出して判定に用い、demosaic を完全に
スキップする。埋め込みプレビューは長辺2〜4K程度でグリッド判定には十分。プレビューを持た
ないファイルはスキップしログ退避する(フル RAW デコードへのフォールバックは速度予算を
壊すため行わない, §5.2)。

### 6. XMP 書き込み

FastRAWViewer が読み書きする標準フィールド `xmp:Rating`(-1〜5, -1は Reject)を使う。

score→Rating マッピング(2026-06-30 レビュー済み rating≥1 プールで暫定校正, §6.2)。score は
`min(center/center_norm + surround/surround_norm, 1.0)`。右列はそのプールでの良品率:

| score | Rating | 良品率 |
|-------|--------|--------|
| < 0.3725 | -1 | (未レビュー主体・不明) |
| 0.3725〜0.5217 | 1 | 2.9% |
| 0.5217〜0.7242 | 2 | 13.3% |
| 0.7242〜1.0 | 3 | 33.8% |
| = 1.0 (上限) | 4 | 57.0% |

Rating 0 は使わない: 多くのビュワーで 0星/未評価 と同じ表示になり、レーティングしない
非流し撮り(§4.5)と区別できないため、低スコアは -1(Reject) に集約する。

境界値そのものは上位区間に含める。境界は暫定で、旧ツールが rating≥1 とした行のみレビュー
済みのため、新指標で dry-run→上位を再レビューして確定する必要がある(feedback-loop)。

既存メタデータの保護(§6.3) — XMP には FastRAWViewer 等が書いた他メタデータが含まれうる
ため、既存を更新モードで開き Rating のみ上書きする。ファイル全体の再生成は避け、名前空間
宣言や既存プロパティを破壊しない Exempi ベースの python-xmp-toolkit を用いる。書き込みは
一時ファイル経由で原子的に置き換える。

### 7. 性能・並列化

1枚あたりの直列処理時間見積り:

| 処理 | 想定 |
|------|------|
| 埋め込み JPEG 抽出 | 20〜50ms |
| JPEG デコード + リサイズ | 10〜30ms |
| グリッド Laplacian スコア | 5〜15ms |
| XMP 書き込み | 5〜10ms |
| 合計 | 40〜105ms |

並列化(§7.2) — CPU バウンドかつネイティブライブラリ主体のため GIL を回避してプロセス並列
(`multiprocessing`)を採用する。macOS では fork がネイティブライブラリと相性が悪いため
`spawn` を使う。ワーカー数は Apple Silicon の性能コア数を基準とする。各ワーカーが
抽出→スコア→変換→XMP書き込みを独立して完結させ、I/O もプロセス内に閉じる。

スループット(§7.3) — 直列平均80msとすると8並列で実効約10ms/枚 → 1万ファイルで約100秒。
オーバーヘッドを見込んでも20〜30分予算内に十分収まる。

### 8. 実行モード

- ドライラン(§8.1) — XMP へ書き込まず、スコアと Rating 候補を CSV へ出力。閾値調整・分布
  確認に使う。
- 本番実行(§8.2) — 閾値確定後、XMP へ Rating を書き込む。サイドカーが存在しない場合は
  新規作成する。
- 推奨運用手順(§8.3) — 上記「推奨運用手順」を参照。
- CSV から適用(§8.4) — dry-run で出力した CSV を高コスト計算(score, EXIF)のキャッシュとして扱い、
  `--from-csv` で XMP を更新する。再スコアリングせず Rating 写像と流し撮り判定のみを現在の設定で
  再適用するため、閾値・判定係数を調整して素早く反映できる。`--from-csv --dry-run` は書き込まず
  再マッピング後の Rating 分布のみ確認する。CSV に focal_length / shutter_denom が無い(旧CSV)場合は
  流し撮り判定は不能扱い(fail-open)で全件レーティングする。

### 9. エラーハンドリング

| ケース | 対応 |
|--------|------|
| 埋め込みプレビューなし | スキップ、ログ退避 |
| プレビューのデコード失敗 | スキップ、ログ退避 |
| XMP 書き込み失敗 | 当該ファイルのみ失敗として記録、全体継続 |
| 非流し撮り(焦点距離/シャッターで判定) | レーティングせず non_panning として記録 (設計 §4.5) |

いずれの失敗も全体処理を止めず、完了後にサマリと失敗ファイル一覧を出力する(NFR-3)。
(元設計 §9 の「サイドカーが無ければスキップ・新規生成しない」は採用せず §8.2 に一本化した。)

### 10. 調整対象パラメータ

| パラメータ | 初期値 | 説明 |
|-----------|--------|------|
| ダウンサンプル長辺 | 1600px | 判定用画像サイズ。速度と精度のトレードオフ |
| グリッド分割数 N | 4 | N×N。構図依存性に影響 |
| center_norm / surround_norm | 737 / 224 | スコア合成 min(center/center_norm+surround/surround_norm,1) の正規化 |
| Rating 境界 | §6.2参照 | score → Rating の境界値(暫定) |
| panning_shutter_factor | 5.0 | 流し撮り判定係数 (シャッター分母 < 焦点距離/factor で流し撮り) |

### 11. 未決事項

- 被写体が中央にない構図への対応(グリッド固定方式の限界)
- 絶対シャープネス足切り閾値の決定(実データ分布待ち)
- 精度不足時に被写体検出(YOLO 等)を導入するかの判断(速度予算との兼ね合い)

## 設計との差異メモ

- スコアの基準を「中央/周辺比」から「中央の絶対シャープネス」へ変更した。2026-06-30 の
  実データ(選別済み1812枚)で比は人間の採否とほぼ無相関(AUC≈0.4)、絶対シャープネスが
  有効(AUC≈0.8)だったため (設計 §4, §6.2)。
- Rating 境界と `center_norm` はこの撮影で校正済み。別の撮影では `--dry-run --csv` を実行し
  `_Rejected` 等の正解と突き合わせて再校正する (設計 §11)。
- 原設計に無い「流し撮り意図の判定」を追加した。非流し撮り(焦点距離とシャッター速度で判定)は
  レーティングしない (設計 §4.5)。
- 原設計に無い「CSV からの適用」を追加した。dry-run→本番の二段運用で書き込み時の再スコアリングを
  避けるため (設計 §8.4)。
- Rating 0 は使わない。ビュワーで 0星/未評価 と同じ表示になり非流し撮り(レーティングなし)と
  区別できないため、低スコアは -1 に集約した (設計 §6.2)。

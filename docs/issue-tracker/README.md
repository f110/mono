# 内部向け Issue Tracker — 検討メモ

Status: Draft / Working

内部向けの issue tracker を検討する。カスタマイズ性は重視せず、差分との紐づけとコーディングエージェントからの操作を中心に据える。

モック: `mock/index.html` をブラウザで直接開く（静的HTML + JS。データは localStorage に保存され、ヘッダの「データをリセット」で初期化できる）。

## 決定事項

### チケット

- 番号は全体で1つの連番。URL は `/<番号>` でソフトウェア分類を含まない
- 本文・コメントはすべて Markdown。`#123` で他チケットへリンク
- ステータスは固定で、遷移フローは強制しない
    - Open / In Progress / Done / Won't Fix
- 優先度は任意フィールドで P0〜P4
- ソフトウェア分類は任意フィールド。分類はマスタで管理し、チケットはIDで参照する
- 添付ファイルをサポートする
- 期限・見積・スプリントなどチーム開発向けの機能は持たない
- エクスポート機能は持たない（自前インフラにデプロイする）

### チケット間の関連

| 種別 | 正方向 | 逆方向 |
| --- | --- | --- |
| parent_of | 親 | 子 |
| blocks | ブロックしている | ブロックされている |
| duplicate_of | 重複元 | 重複 |
| relates_to | 関連 | 関連 |

関連は有向の1レコード (`from`, `type`, `to`) として保存し、逆方向は表示時に導出する。

### 差分との紐づけ

- リポジトリは独立したエンティティ（ID・名前・URL）として管理する。紐づけ側は `repo_id` を持ち、commit や PR の URL は表示時に組み立てる。リポジトリが移動しても URL の更新は1箇所で済む
- デフォルトブランチへの push では、各コミットの trailer を読み取り、コミットをチケットに紐づける。commit hash と jj の change-id を記録する
- PR イベントでは、PR に含まれるコミットの trailer を読み取り、PR 自体をチケットに紐づける
- trailer は2種類
    - `Refs: <番号>`: 紐づけのみ
    - `Fixes: <番号>`: 紐づけに加えて、デフォルトブランチへの push 時にチケットを Done にする
- 紐づいた差分には Build (CI) の結果を表示する

### 操作主体と権限

- 人間とエージェントでトークンを分ける
- エージェントトークンは所有者（人間）を持つ
- すべての操作履歴（作成・ステータス変更・優先度変更・分類変更・担当変更・関連の追加/削除・コメント・添付・本文編集）に操作主体と、それが人間かエージェントかを記録する
- `Fixes:` による自動的なステータス変更など、サーバーが行った操作は操作主体を「システム」として記録する
- チケットに関する操作は人間とエージェントで同じことができる
- リポジトリの追加などの管理機能は人間のみ

### インターフェース

- Web UI
- 人間向けの CLI
- エージェント向けの MCP

### 認証

- サーバーは heimdallr のプロキシの後ろに置く。人間はプロキシが付与する認証ヘッダーで認証する

### 添付ファイル

- 保存先はオブジェクトストレージ
- サイズの上限は設けない

### 一覧

- 全文検索とステータス・優先度・分類・担当でのフィルタ
- 検索条件は URL のクエリに反映し、URL で共有できるようにする

# azimuth — 撮影スポット探索ツール 検討メモ / PRD

Status: Draft / Working

## 1. 背景

低い高度の太陽・月と対象物（山・塔・建物など）が、写真の構図としてよい位置に並ぶ撮影地点と日時を探したい。

既存のツールにはそれぞれ足りない点がある。

| ツール | できること | 足りないこと |
| --- | --- | --- |
| [hinode.pics](https://hinode.pics/) | 地図上の地点の日の出・日の入・月の出・月の入の時刻と方角。日付の指定 | 標高・地形を考慮しない。対象物との位置関係を計算しない |
| [ダイヤモンド・パール富士マップ](https://decoincidence.jp/fuji) | 指定日に太陽・月が富士山頂に重なって見える地点の線。前後の日の線。遮蔽標高図 | 対象が富士山に限られる。観測地は標高 0m として計算する |

hinode.pics と同じ基本機能を自作し、そこに「任意の対象物に太陽・月が重なる地点と日時の探索」を加える。

## 2. 目的とスコープ

### 2.1 目的

- 撮影計画の段階で、対象物・日付・太陽か月かを決めると撮影できる地点が地図上で分かる
- 撮影地点と対象物を決めると、太陽・月が対象物に重なる日時が分かる
- 現地でスマートフォンから、今いる場所の出入りの方角・時刻と対象物の方角を確認できる
- 観測地と対象物の標高、地球の曲率、大気差を計算に入れ、山岳地でも使える精度にする

### 2.2 利用者・運用

- 利用者は自分だけ。複数ユーザー・権限管理は持たない
- 自宅の Kubernetes クラスタにデプロイし、他の内部サービスと同じく heimdallr proxy の後ろに置く
- Web アプリとし、PC とスマートフォンの両方のブラウザで使える

### 2.3 スコープ外

- 重なっているかどうかの判定。ツールは方位角・高度のずれを数値で出し、判断は利用者が行う
- push 通知・メールなどアプリの外への通知
- オフラインでの利用
- 写真の投稿・共有、SNS 連携
- 一般公開・会員機能
- 天気予報との連携（今後の課題。`go/jma` が使える可能性がある）
- 天の川・星の撮影計画（夜間の天体全般）

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 観測点 | カメラを置く地点。緯度・経度・地表の標高・三脚の高さ |
| 対象物 | 太陽・月と重ねたいもの。緯度・経度・標高（建造物は地表の標高 + 高さ） |
| 天体 | 太陽または月 |
| 方位角 | 真北から時計回りの角度 |
| 視高度 | 観測点から見た天体の高度。大気差・視差を補正したもの |
| 見かけの仰角 | 観測点から見た対象物の仰角。地球の曲率と地上の大気差を補正したもの |
| ずれ | 天体の中心と対象物の頂点の、方位角の差と高度の差（視高度 − 見かけの仰角） |
| 撮影条件 | 観測点・対象物・天体・時間帯（昇る/沈む/視高度の範囲）の組 |
| 地形の稜線 | 観測点からある方位を見たときに、地形が最も高く見える仰角 |

## 4. ユースケース

### UC1: 日付と対象物から撮影地点を探す（日付→地点）

2026-11-09 の日の入に太陽が対象の山頂に沈む光景を撮りたい。地図上に、その光景が見える地点が線で表示される。
線上の地点をクリックすると、時刻・距離・観測点の標高・遮るものの有無が分かる。前後の日の線も表示され、日付を
ずらしたときに線がどこへ動くか分かる。

### UC2: 撮影地点と対象物から日時を探す（地点→日時）

いつも行く展望台から、遠くの鉄塔に月が重なる日時を知りたい。期間（例: 今後1年）を指定すると、天体の方位角が
対象物の方位角と一致する日時の一覧が出る。各候補に天体の視高度・高度のずれ・月齢が付き、重なるかどうかは数値を見て判断する。

### UC3: 地点の出入りの方角と時刻を確かめる（hinode.pics 相当）

地図上の地点にマーカーを置き、日付を選ぶと、日の出・日の入・月の出・月の入の時刻と方角が線で表示される。
標高と地形を考慮し、「山の稜線から実際に日が昇る時刻」も出る。

### UC4: 現地で確認する

スマートフォンで現在地を観測点にし、対象物の方角・距離・仰角と、今日の天体の軌跡を地図上で見る。

### UC5: 対象物を登録する

よく使う対象物（山頂、塔、灯台など）を名前を付けて保存する。地図上の任意の点を対象物にすることもでき、
その場合の標高は標高データから自動で取る。建造物は地表からの高さを入力する。

### UC6: 保存した撮影条件の候補日を確認する

UC2 の撮影条件を保存しておく。アプリを開くと、保存した撮影条件ごとに今後の候補日時がずれの数値付きで一覧になっていて、
撮影に行く日を決められる。

## 6. 非機能要件

- 精度
    - 天体の方位角・視高度の誤差は 0.01° 以下（天体の視半径 約0.25° に対して十分小さい）
    - 出入りの時刻は国立天文台 暦計算室の値と ±1 分以内で一致する（水平線基準）
    - 地平線付近の大気差は気象条件で 0.1°〜0.2° 程度ぶれる。この不確かさは計算で消せないので、画面に注記する
- 性能
    - A-1（1日分）の結果を 3 秒以内に表示する
    - A-5（1年分）の結果を 10 秒以内に表示する
- スマートフォンの縦画面で主要な操作ができる
- 時刻は JST で表示する。内部では UTC で扱う

## 7. 計算の検討

### 7.1 重なりの条件

観測点 P、対象物 T について次の2つが一致すると、天体の中心が対象物の頂点に重なる。ツールは両者の差をずれとして出す。

- 天体の方位角 = P から T への方位角
- 天体の視高度 = P から見た T の見かけの仰角

P と T の距離を d、標高を h_P（三脚の高さを含む）、h_T、地球の半径を R、地上の大気差係数を k（標準 0.13）とすると、
見かけの仰角は近似的に次のとおり。

```
θ ≈ (h_T − h_P) / d − d (1 − k) / (2R)   [rad]
```

富士山（3776m）を 100km 先、標高 0m から見ると θ ≈ 2.16° − 0.39° = 1.77° になる。曲率の項は無視できない。
decoincidence は観測地を標高 0m としているが、このツールでは h_P に標高データの値を入れる。

### 7.2 日付→地点（A-1）

1. 対象の時間帯（例: 日の入の前後で視高度 -1°〜15°）を 10 秒刻みで走査し、各時刻 t の天体の方位角 A(t)・視高度 a(t) を求める
2. T から方位 A(t) + 180° の方向へ半直線を伸ばし、距離 d ごとに標高データから h_P(d) を取って θ(d) を求める
3. θ(d) = a(t) となる d を求める（地形によって複数の解がありうる）。これが時刻 t の観測点の候補になる
4. 時刻順に候補をつなぎ、地図上の線にする
5. 各候補について、P→T の断面で地形が視線を遮らないかを判定する（A-3）
6. 月は地心と観測点での視差が最大約 1° あるため、得た P で視高度を計算し直して d を補正する。P が 100km 動いても視差の変化は約 0.015° なので、補正は 1 回で足りる見込み

探索する距離 d の上限は、T の頂点が地球の曲率で見えなくなる距離までとする（3776m なら約 230km）。

### 7.3 地点→日時（A-5）

P と T が決まると、方位角 β と仰角 θ が決まる。期間内で天体の方位角が β になる時刻を探し、その時刻の視高度と θ の差を出す。
太陽は年に2回前後の期間に、月は月に1回程度の頻度で候補がある。

### 7.4 天体位置の計算

| 案 | 内容 | 評価 |
| --- | --- | --- |
| 自前実装（Meeus の Astronomical Algorithms） | 太陽は VSOP87 の簡略版、月は ELP2000 の主要項。誤差は太陽約 1″、月約 10″ | 精度は要件を満たす。依存がなく、計算が軽い |
| JPL DE440 などの暦表 | 最も精度が高い | 暦表ファイル（数十 MB）の配布が必要。この用途には過剰 |
| 既存の Go ライブラリ | 例: 出入りの計算だけを持つもの | 視差・任意高度の扱いが足りないことが多い |

推奨は自前実装。国立天文台 暦計算室の値でテストを作り、精度を確認する。
大気差は視高度に応じた式（Bennett の式など）を使い、気温・気圧は標準値に固定する。

### 7.5 計算をどこで行うか

| 案 | 長所 | 短所 |
| --- | --- | --- |
| サーバー（Go） | 標高データのキャッシュを1か所に持てる。リポジトリの他のサービスと同じ構成で作れる | 計算ごとに通信が必要 |
| ブラウザ（TypeScript） | 計算に通信が要らない | 標高データをブラウザで大量に取る必要があり、スマートフォンでは A-1 が遅い |

推奨はサーバーでの計算。

## 8. データ

### 8.1 標高データ

| データ | 解像度 | 範囲 | 用途 |
| --- | --- | --- | --- |
| 国土地理院 標高タイル（DEM5A/5B/5C/10B） | 5m / 10m | 日本 | 主に使う。観測点・対象物の標高、断面、稜線 |
| Copernicus DEM GLO-30 | 30m | 全世界 | 海外で使う場合（P2） |
| PLATEAU / AW3D などの DSM | - | 一部地域 | 建物・樹木の遮蔽（A-7, P2） |

- 標高タイルは必要な範囲をサーバーが取得し、ストレージ（MinIO）にキャッシュする
- 国土地理院コンテンツ利用規約に従い、出典を画面に表示する

### 8.2 保存するデータ

- 対象物: 名前、緯度経度、地表の標高、地表からの高さ、メモ
- 観測点のお気に入り: 名前、緯度経度、標高、三脚の高さ、メモ
- 撮影条件: 名前、観測点、対象物、天体、時間帯

利用者が1人でデータが少ないため、既存の MariaDB に置く。

## 9. 全体構成（案）

```
  Browser (PC / スマートフォン)
     │
     ▼
  heimdallr proxy
     │
     ▼
  server (Go)  ── Connect API
     ├── 天体位置の計算
     ├── 重なりの探索
     └── 標高データの取得 ──▶ 国土地理院 標高タイル
             │
             ▼
           MinIO (標高タイルのキャッシュ)
  MariaDB (対象物・観測点)
```

- フロントエンドは `ts/apps/` に置く。地図は MapLibre GL JS か Leaflet で地理院タイルを使う
- 天体計算と標高データの取得は、サーバーから切り離した Go のパッケージにする（テストしやすくするため）

## 10. 検証方法

- 出入りの時刻・方位角: 国立天文台 暦計算室の値と比較する
- 重なりの探索: ダイヤモンド・パール富士マップで富士山を対象にした結果と、複数の日付で線の位置を比較する
  （観測地の標高の扱いが違うので、標高の低い地域で比較する）
- 実際に撮影して、予測した時刻・位置とのずれを記録する
